# Migration to the manifest-driven documentation engine

## Purpose

This note describes the change from the combined `docs/manifest.json` model to one manifest per generated document.

## What changed

The maintained manifests are now stored in `docs/manifests`. `config/documentation.json` defines only global paths, tool settings, project metadata and common document defaults. The PowerShell engine enumerates the configured manifest pattern and does not contain guide names.

The old `docs/manifest.json` is retained as a deprecation pointer so existing links fail gracefully. It is no longer read by the build.

The initial document ids are:

| Manifest id | Output base name | Primary audience |
|---|---|---|
| `TechnicalUserGuide` | `OpenData-Technical-User-Guide` | Operators and technical users |
| `AdministratorGuide` | `OpenData-Administrator-Guide` | Platform, database and operations administrators |
| `DeveloperGuide` | `OpenData-Developer-Guide` | Maintainers and plugin developers |
| `APIReference` | `OpenData-API-Reference` | Integrators and support engineers |

## Command migration

Load the function once in the current PowerShell session:

```powershell
. .\scripts\Invoke-Documentation.ps1
```

Build every manifest:

```powershell
Invoke-Documentation -Action All -Format All
```

Build one document:

```powershell
Invoke-Documentation -ProjectRoot $PWD -Action Build -Document DeveloperGuide -Format Docx
```

The previous fixed values `Technical` and `User` are no longer PowerShell validation-set values. The unconditional workstation-specific invocation formerly at the end of the engine has been removed. Select a manifest by id, manifest filename without `.json`, or output filename without its extension.

## Front matter and TOC

The assembly order is now:

1. Cover page.
2. Copyright page.
3. Revision history.
4. Table of contents.
5. Ordered document sections.

The TOC is inserted by `docs/_filters/document-toc.lua` at the `.document-toc` marker generated by the engine. The global Pandoc `--toc` switch has been removed. Automatic HTML and PDF title blocks are also suppressed so no writer-generated content precedes the cover. DOCX output contains a native Word TOC field and requests field refresh when opened.

## Adding another guide

1. Add or reuse Markdown under `docs`.
2. Copy a JSON file in `docs/manifests`.
3. Assign a unique `id`, `title`, and `output`.
4. Define the ordered `sections` list.
5. Run validation and then `-Action All`.

No PowerShell change is required.

## Overlay instructions

Expand the supplied overlay ZIP at the repository root and allow matching files to be replaced. Java source is intentionally absent from the overlay.
